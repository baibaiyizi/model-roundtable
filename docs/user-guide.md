# 模型圆桌

中文 Windows 桌面应用：项目下保存多个聊天，多模型讨论后把方案交给 Agent 修改代码与本地资料，再由多个模型审阅。原创源码采用 MIT 许可。

## 开始使用

1. 安装 `Model-Roundtable-1.0.0-win-x64.exe`。
2. 在“模型与设置”选择 DeepSeek、Kimi 或自定义 OpenAI 兼容服务，填写 API 地址和密钥。获取实时模型列表，也可以手填模型 ID，然后测试连接。
3. 新建项目并选择本机工作目录；项目下可建立多个讨论和执行聊天，也可以先进行独立讨论。
4. 选择圆桌、自由群聊或正式辩论。圆桌和群聊主持可选，正式辩论需要裁判。
5. 从讨论选择“执行”，检查任务、完成判定、执行者、审阅者后开始。也可以在项目下直接创建执行任务。

模型设置和网络设置按栏目折叠；默认展开模型服务、订阅列表和新服务必填项。可全部展开或收起，重新打开会记住展开状态；折叠保留输入、节点选择和检测任务，标题仍显示错误、进度及未保存状态。

连接测试只验证文本能力。“测试执行能力”要求一次结构化工具调用，不执行本机命令。模型、搜索及资料处理使用用户配置的服务，可能产生对应服务费用。

## 项目、执行与审阅

项目保存工作目录、项目说明与默认知识库，各聊天独立保存历史和草稿。切换聊天、关闭标签不会停止后台任务。左侧可筛选项目和会话，使用独立的“⋯”菜单进入设置、导出讨论或删除记录；运行及停止收尾期间须先停止并等待。移除项目会移除关联聊天/执行记录及草稿，不删除项目目录里的文件，也不回滚执行产生的修改。

执行直接修改项目目录，保存任务快照、操作记录、文件差异和验证结果。相同目录及父子重叠目录同时只允许一个执行者写入，其他聊天可继续讨论。外部编辑器不受此锁控制；受控文档操作检查源文件 SHA256，普通终端修改通过运行前后比较核对，不承诺完整归因或自动回滚。不会自动初始化 Git、提交、重置或推送。

默认一位执行、多位只读审阅。初次审阅后最多两轮自动修复与复核，仍有问题交回用户。审阅保留分歧，不能把多数同意当作正确率。结果状态、文件清单和结果摘要回贴来源讨论；打开项目下的执行会话，可查看实际文件、差异、验证和未解决问题。

API 执行复用固定版本 OpenCode。应用本机请求控制层锁定服务和模型，在转发前记录调用次数，辅助请求也计入预算。首个接口错误或断流后不再放行新上游请求，用户可以明确重试。已发出的请求是否计费由服务方决定，未返回用量不记为零。

开始任务授权范围内的文件修改与本机命令。命令以当前 Windows 用户身份运行，项目目录不是操作系统沙箱。发布、上传和超出任务范围的操作不包含在普通开始执行中。本轮不包含浏览器/桌面自动操作。用户项目缺少自己的编译器或依赖时会明确报告。

停止会取消后续请求并终止后台进程树，保留实际已发生的修改。重启不会自动重放付费请求或状态不明的命令。

## 官方账号

设置中可准备固定版本的 Codex、Claude Code 官方组件，再完成官方登录。Claude Code 可选择订阅或 Anthropic Console 登录，也可在 Claude 服务中选择自有 Anthropic API Key；密钥仅交给对应服务的原版 CLI 子进程。高级入口可打开同一独立 profile 的官方 Claude Code。首次准备需要联网下载并校验 SHA256，用户无需手工安装 CLI 或开发环境。

使用独立的官方登录目录，不读取浏览器 Cookie，不复制订阅令牌。可用模型及额度由官方服务决定，网页订阅不是通用 API Key。讨论/审阅关闭执行能力，实际执行按任务授权。

官方后台内部 HTTP 次数无法像 API 控制层一样精确统计，界面记录后台启动及返回用量，不编造费用。Kimi/Gemini 通用订阅接入不在此版本范围，Kimi 可使用公开 API。

输出 Token 硬上限仅 API 接口可保证。Claude Code 使用官方提供的输出设置，但其内部请求不全适用；Codex 当前没有等价的逐回答硬限制，只收到长度提示。官方后台仍受应用的任务超时和停止控制。

## 三种讨论模式

| 模式 | 行为 |
| --- | --- |
| 圆桌 | 相同材料上的独立首轮、交叉评议。无主持时各自给出结论，可另选模型总括；支持追加评议。 |
| 自由群聊 | 有主持时由主持选人；无主持时成员基于同一记录申请发言，优先最久未发言者，同等情况按席位顺序。无人申请时暂停。 |
| 正式辩论 | 双方独立立论、质询及回答、反驳、双方总结、裁判评议。必要席位失败须重试或结束。 |

无主持群聊通常需要 N 次申请加一次正式发言；申请、搜索规划、摘要及查询 Embedding 均计入模型调用上限。成功申请保留，申请失败时可重试失败部分或结束。点名绕过自动申请；静音只影响自由群聊自动发言。

暂停等待当前发言或申请批次完成；插话立即中断生成并重建上下文；单次发言在下一条正式回答后暂停。迟到结果不能恢复旧任务。完整记录持续保存，长讨论由主持或轮换成员整理带来源映射的摘要，摘要不是原始证据。

模板保存讨论配置，丢失的模型或知识库引用需要重新选择。自由群聊可从完整发言创建分支，圆桌/辩论从已完成阶段创建；分支保留历史前缀和证据快照，独立预算，初始暂停。

## 搜索和知识库

默认免 Key 网页搜索，可选 Bing、百度或 Google；Tavily、自配 SearXNG 为可选来源。SearXNG 必须启用 JSON 接口。搜索使用独立浏览器会话，遇验证码显示窗口供人工处理，然后手动重试。页面变化、网络限制及验证码可能导致失败，不自动切换付费服务。

新讨论和执行任务默认允许自动联网，默认不限制搜索次数；高级设置可设上限，已有会话、模板和草稿保留原设置。每次查询保存最多五条去重结果，尝试提取前三条正文；摘要与正文分别标注，提取失败保留原因。搜索来源及线路在任务开始时固定，手动搜索也计入次数。暂停后可补充搜索；独立首轮期间改变共同材料会重新开始首轮，确保材料一致。取消搜索次数上限不取消模型调用、输出、任务时长和网络超时限制。

OpenCode、Codex、Claude 执行后台通过应用内置工具通道按需搜索和读取网页，无需安装搜索 MCP 或填写搜索 Key。各后台原生搜索继续关闭；网页和搜索结果保存来源、时间、线路和证据，供执行审阅使用。联网失败显示原因，不自动切换来源或重复付费搜索，用户可明确重试；浏览器验证码须人工处理。

知识库按集合保存，可跨项目和聊天选择。支持 PDF、扫描页、DOCX、PPTX、UTF-8 文本/Markdown、Excel/CSV、普通网页、图片、音视频。扫描页和图片使用指定视觉模型，音频按实际分片转录，视频结合音轨与抽样帧，不代表完整连续动作理解。

PPTX 使用按需文档组件完整提取每张幻灯片的文字和表格，递归读取组合形状，引用保留幻灯片序号；不复用有截断的预览结果。纯图片演示稿明确提示没有可索引文字；不执行 PPTX OCR、不分析动画或 SmartArt。超限、取消或输出不完整明确失败，不把部分内容标为处理完成。

Embedding、视觉与转录分别配置，不从模型名字猜能力。知识库绑定 Embedding 服务、模型和维度，更换需要明确重建。只有完成的资料参与检索；会话保存实际证据快照，资料更新不会改写历史引用。

## 与 VS Code 一起使用

应用已经可以通过执行任务修改项目文件，内置文件面板仍是预览。手动编辑、语言服务和第三方插件继续由 Windows 本机 VS Code 提供，无需把 VS Code 本体装入圆桌。

1. 安装 VS Code 1.138 或更新版本；进入圆桌“模型与设置 → 编辑器协同”安装／更新伴随扩展，必要时重新加载 VS Code。也可从 VSIX 安装 `model-roundtable-companion-1.0.0.vsix`。检测到编辑器不代表扩展已经安装。
2. 在 VS Code 直接右键发送，首次在圆桌点击“允许连接”。不输配对码，不要求同一项目，不必打开文件夹；同一 VS Code 用户配置中的其它本机窗口共用连接。圆桌需保持运行，主动关闭的资料连接需要先重新开启。
3. 在 VS Code 编辑区选中文字，右键“模型圆桌：发送选中文本”；当前文本文件也可通过相应命令发送。PDF/Office 文件在左侧资源管理器右键“模型圆桌：导入资料到知识库”。回圆桌点击收到资料后显示的“VS Code 资料”确认目标。文本追加到讨论或执行草稿，不自动启动模型；文件确认集合后才开始解析和可能收费的 Embedding/视觉调用。
4. 收件箱可选择独立讨论、任意项目讨论或新执行草稿；执行草稿才要求明确工作目录。圆桌结果可发送为新的未保存 Markdown 文档及原生预览，不覆盖原件。一个在线窗口直接接收，多个窗口明确选择。

保留文本文件名、相对路径、行号、时间、哈希及未保存标记；追加后的整个正文最多 20,000 字符，不静默截断或覆盖已有草稿。传输先保存并去重，失败可手动重试原快照，重启不自动启动模型。不能追加已有执行记录时，选择同项目的新执行草稿。

“编辑器协同”按安装扩展、连接状态和使用说明整理，完整路径及手动安装方法放在折叠说明中。左侧“VS Code 资料”仅在存在待接收或导入记录时显示，数量与收件箱一致；已追加或移除的记录不计入，最后一条记录处理完后隐藏。

支持可信的 Windows 本机环境中的单文件、未命名文本和未保存修改；不接入 Remote/SSH、WSL、浏览器版或虚拟工作区。伴随扩展不读取其他插件的 Webview，不提供任意命令或写文件接口，第三方插件继续使用自己的权限、账号和网络。第三方 PDF / Draw.io 插件不属于本版保证范围；不代表日常 VS Code 已安装插件。安装与排错见 [VS Code 协同指南](editor-guide.md)，实际验证见 [验收记录](../VALIDATION.md)。

## 创建和修改文档

所有执行后台共用按需准备的固定 CPython 文档服务，支持 TXT/Markdown/JSON/CSV 及普通 DOCX/XLSX/PPTX/PDF 的创建和修改。用户不需要安装 Python、pip、Office 或 LibreOffice。

编辑采用源文件 SHA256、修改前备份、临时输出回读检查和最终替换。超出作者库支持范围的宏、签名、复杂嵌入对象等明确拒绝，不能静默丢弃。旧 `.doc/.xls/.ppt` 不自动转换后覆盖。

Word/PPT 使用按需准备的 LibreOffice 对副本生成预览 PDF，原件不经预览转换另存；预览不能保证与 Microsoft Office 完全一致。Excel 用网格预览，不进入 Calc、不重算公式、不执行宏，失效缓存显示未计算。PDF 支持生成、页面处理、表单及叠加，不承诺任意正文重排。

生成和预览分别记录状态；预览失败不能标为全部验收成功。工具和运行时详细范围见 [文档组件说明](../resources/documents/README.md)。

## 扩展商店与按需组件

左侧“扩展商店”提供 MCP 与 Skill 的搜索、详情、安装、配置、连接测试、更新检查和卸载；也可导入 MCP JSON、Skill 文件夹/ZIP 或公开 GitHub 来源。MCP 目录来自官方 Registry，Skill 搜索使用官方 CLI 使用的公共入口。目录条目不是可用性或安全审计保证，不支持的包类型会显示所需环境。

首次打开显示常用推荐：Context7、Brave Search、Playwright，以及 Frontend Design、Web Design Guidelines、React Best Practices。推荐仅展示用途、来源、Key 和运行环境要求，不会自动安装或授权。排序仅针对已加载结果；GitHub Stars 属于仓库，同仓库 Skill 共用，安装量按技能展示。仅在选择 Stars 排序或打开详情时补充星数，缓存 24 小时；限流停止补充，未知值显示“暂无数据”。

安装失败可展开详情、移除单条记录或清除全部已结束记录，运行中仅可取消。清理结果重启后保留，不卸载扩展、不清除真实连接故障。已安装扩展可重新配置和测试，成功后清除旧连接错误。

在项目页逐个启用扩展并核对工具定义和权限。讨论仅获得明确授权的读取工具，开局最多选择四次读取，工具准备的模型调用计入总预算；工具结果在独立首轮前共享。执行可使用项目写入工具，外部操作每次单独确认。MCP 注解与 Skill 的 allowed-tools 不授予权限。工具代理是应用层授权，不是操作系统沙箱。

Skill 通过锁定的官方 CLI 安装到私有目录，保留资源、来源、提交、许可与文件哈希。安装及讨论不自动执行脚本。检查更新只比较版本，点击更新才准备新快照，运行中的任务继续使用原快照。模型只获得本次本机代理访问权限，上游连接凭据加密保存。

项目页可将授权的 MCP 读取工具指定为搜索来源，填写查询参数及结果字段。没有真实 HTTP(S) URL 的内容显示为工具结果。取消绑定后使用设置中的默认免 Key 搜索。

“组件中心”显示固定版本、下载和解包进度，可取消、失败重试、导入对应官方原始包或卸载。首次使用执行、Office/PDF 编辑、Word/PPT 预览和知识库时按提示准备 OpenCode、Python 文档库、LibreOffice 或 LanceDB。Node/Python/Git 等扩展环境由应用准备。组件缓存在固定数据目录的 components 下，更新主程序可复用，卸载组件不删除资料和账号；已加载的原生组件需重启后切换。

结构化任务先严格解析 JSON，仅接受完整前置思考块和外层代码围栏；不猜测缺失字段。失败保留本机原响应、模型、阶段与结束原因；普通讨论文本不清理。模型设置中可明确测试 JSON Schema/JSON Object，成功后才启用原生协议。测试会调用一次模型，不自动追加付费重试。

## 固定数据目录

数据库、密钥、知识库、账号资料、文档备份、草稿和运行记录固定保存在 `%APPDATA%/model-roundtable/v2`。v2 是固定数据目录名，不随应用版本变动；覆盖升级继续使用同一目录。项目文件仍在用户绑定的目录里。`模型与设置 → 检查旧模型配置` 可只读预览早期根目录的旧库，备份当前库后一次性导入。相同 ID 保留当前项，相同地址默认跳过，明确勾选后另存服务；无法解密的密钥会说明原因。没有通用迁移框架，不支持的数据版本明确报错。

API Key 使用 Windows 系统保护能力加密保存。调用模型时，任务、相关资料摘录及必要文件内容会发送到所选服务；视觉、Embedding 和转录同理。应用没有账号体系、云同步或公共模型服务。

密钥解密还需要同一数据目录的 `Local State`，备份应保留完整 v2 目录。一次性恢复旧服务会复制旧 Local State 到临时独立进程，用 Electron 官方 safeStorage 解密，再由当前目录重新加密；旧目录保持只读。

## 每个服务的网络与订阅

“网络与订阅”支持导入 Clash/Mihomo 兼容链接或本地文件，查看节点、手动更新及检测延迟。选择好节点后，在模型服务设置中指定“跟随系统 / 直连 / 订阅节点”。同一服务下所有模型使用该线路，模型选择框也会显示线路并提供设置入口。例如 OpenAI 使用节点 A、Anthropic 使用节点 B，DeepSeek 和自部署服务直连，可在同一场讨论中使用。

Mihomo 1.19.31 内核随包，首次使用自动校验准备，无需另装 Clash、管理员权限或系统代理。搜索、网页资料、HTTP MCP、商店、下载、订阅更新和官方账号管理各自可选线路；账号讨论和执行按模型服务的线路。系统浏览器登录页面仍使用浏览器的网络；任意终端软件是否遵循代理环境变量由该程序决定。

节点手选固定，失败不会自动换节点、直连或重放模型请求。活动任务保留线路快照，设置修改和订阅更新待任务结束再生效。订阅更新失败保留上次有效内容，所选节点消失时必须重新选择。节点测速不调用付费模型，也不代表目标模型可用；请另外运行服务连接测试。

节点列表可按名称筛选、全选当前筛选并批量检测，最多并发三个；取消保留已完成结果，不修改服务绑定、不自动挑选最快节点。应用线路有未保存提示、撤销入口和离开页面的保存/放弃提示。模型、主持及线路单选可搜索；服务模型、知识库多选支持筛选内全选，保留筛选外选择；成员及审阅者可批量加入，超出席位限制明确提示。

支持含节点的 YAML、节点 URI 和 Base64，以及根配置中的 HTTP/inline 节点集合。导入不执行原订阅中的系统路由、脚本、控制接口或任意本机文件引用。不支持的协议、嵌套或代理链依赖会报错；商业 VPN 的登录链接不等于兼容订阅。订阅链接与节点凭据加密保存，内核日志不保留原始节点错误。

本机线路只控制到服务地址的连接；远程网关访问上游仍需在网关上配置网络。外部 TUN 可能继续影响本机流量。内核来源、校验及对应源码见 [网络组件说明](../resources/network/README.md)。

## 开发、测试与构建

构建环境：Windows x64、Node.js 24、npm，媒体构建使用 Git for Windows/GPG。运行时由脚本准备。

```powershell
npm ci
npm --prefix vscode-extension ci
npm --prefix vscode-extension run package
npm run media:setup
npm run network:setup
npm run components:setup -- --all
npm run dev
```

```powershell
npm run typecheck
npm test
npm run test:e2e
npm --prefix vscode-extension test
npm --prefix vscode-extension run test:host
npm run dist
npm run source
```

独立 VSIX 与应用必须同版本，构建前先运行伴随扩展的打包命令。归档前将生成的 VSIX 复制到当版暂存目录；安装包内也携带同一文件。源码包包含伴随扩展源码、构建配置和测试，不包含其 node_modules、out、.test* 缓存或 VSIX。

核心构建校验随包媒体与 Mihomo 内核，独立运行环境由组件中心按需准备。`npm run components:setup -- --all` 将锁定官方包准备到 `.cache/components-runtime`，用于完整开发验收；此缓存不打入安装包。`dist` 产物位于 `release/.staging/<版本>/`，完成安装与数据验收、写入 validation.json 后运行 `npm run release:finalize`，独立归档到 `release/<版本>/`。已归档版本不能被覆盖，`release/latest.json` 是唯一最新验收入口。

源码：`src/main/discussion` 负责讨论，`execution` 负责任务/审阅/请求控制，`agents` 负责官方后台，`documents` 负责共用文档工具，`knowledge` 负责解析检索，`projects.ts` 管理目录访问，`editor.ts` 提供认证的本机资料桥接，`vscode-extension` 是独立伴随扩展。渲染界面无 Node 权限，经校验的 IPC 调用后台。

测试结果、复现方法及真实账号/干净系统未验证项见 [VALIDATION.md](../VALIDATION.md)。可控 API 测试不替代真实网关、真实订阅账号或模型质量验收。
