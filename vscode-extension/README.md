# 模型圆桌伴随扩展

将 Windows 本机 VS Code 的选区、当前文本文件、PDF 和 Office 资料送到模型圆桌；接收圆桌的 Markdown 结果。扩展不调用模型、不运行项目脚本，也不覆盖文件。

## 安装后直接发送

1. 需要 VS Code 1.138 或更新版本。在圆桌「模型与设置 → 编辑器协同」安装／更新伴随扩展，或从 VSIX 安装 `model-roundtable-companion-1.0.0.vsix`；必要时重新加载窗口。
2. 圆桌保持运行。在 VS Code 编辑区选中文字，右键「模型圆桌：发送选中文本」，首次在圆桌点击「允许连接」。
3. 以后直接右键发送到统一收件箱，不输入配对码、不绑定项目、不在 VS Code 选择目标。同一 VS Code 用户配置的其它本机窗口复用凭据。
4. 回圆桌点击「VS Code 资料」，选择独立讨论、任意项目讨论、新执行草稿或知识库。只有执行草稿需要选择实际工作目录，资料来源无需相同。

不必打开文件夹。支持单个本机文件、未保存修改和未命名文本；文字取自当前缓冲区，保留文件来源、行号、时间和哈希，不强制保存。正文及追加后的草稿最多 20,000 字符，超限不截断。

PDF、DOCX、XLSX、XLS、XLSM、CSV、PPTX 从资源管理器右键「模型圆桌：导入资料到知识库」，或从命令面板选择。文件确认原件和集合后才开始解析、视觉或 Embedding。来源失效或链接改向需重新发送。接收本身不启动模型、不执行任务、不打断发言。

## 连接与重试

首次连接申请五分钟有效，可拒绝或取消；不会自动反复申请。圆桌未启动或用户关闭资料连接时，先启动或在设置开启。使用「模型圆桌：重新连接应用」检查或重新申请连接；「模型圆桌：查看连接状态」查看当前窗口；「模型圆桌：撤销连接」撤销令牌，也可在圆桌操作。

资料发送失败保留原快照和 ID，运行「模型圆桌：重试未确认传输」手动重试或移除。旧版未发出的本地记录会保留；无法完整确认来源时明确要求重新发送，不猜测路径或用旧协议重放。

读取通道可自动重连，写入资料不会自动重放。多个在线窗口接收圆桌结果时需明确选择一个；结果创建为未保存 Markdown 并打开原生预览，不覆盖文件或广播给其它窗口。

## 本机边界

只支持可信的 Windows 本机 VS Code；Remote、SSH、WSL、浏览器及虚拟工作区不接入。文件必须是本机普通文件，不支持 UNC 共享、设备路径或替代数据流。连接只访问 `127.0.0.1`，从固定数据目录发现端口，不经过代理；认证凭据保存在 SecretStorage，资料及待重试内容存于本机工作区存储，不宣称另行加密。

旧配对凭据继续使用。应用与扩展需要同步更新，协议版本不匹配时明确提示，不混用旧项目绑定协议。隔离验收不会在日常 VS Code 中自动安装扩展。

## 文档插件

Markdown 预览由 VS Code 提供，也可自行使用 [Draw.io Integration](https://github.com/hediet/vscode-drawio) 或 [vscode-pdf](https://github.com/tomoki1207/vscode-pdfviewer)。它们使用自己的账号、权限及网络，圆桌不读取其 Webview，也不把打开文件报告为解析完成。第三方 PDF / Draw.io 插件不属于本版保证范围。

## 构建与测试

```text
npm ci
npm test
npm run package
npm run test:host
npm run test:app-host
```

`test:host` 使用官方 @vscode/test-electron 下载固定的 VS Code 1.138.0，把同版本 VSIX 安装到隔离扩展目录后运行；也可用 `VSCODE_EXECUTABLE_PATH` 显式指定 Code.exe。请先运行 `package`。`test:app-host` 需先构建应用，同时启动真实 Electron 与已安装 VSIX 进行资料往返，不调用收费模型；可用 `ROUNDTABLE_EXECUTABLE` 指定安装版应用。`package` 仅生成本地 VSIX，不发布 Marketplace。实测结果见随扩展交付的 VALIDATION.md。
